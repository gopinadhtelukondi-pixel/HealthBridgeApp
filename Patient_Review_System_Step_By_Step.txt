PATIENT REVIEW SYSTEM - STEP BY STEP IMPLEMENTATION GUIDE
=========================================================

Project: HealthBridge - Transparent Healthcare Decision Platform
Goal: Build a safe, ethical, verified patient review system that helps future patients compare doctors and hospitals using real treatment experiences.


1. WHAT WE ARE BUILDING
-----------------------

The Patient Review System will allow logged-in patients to submit structured reviews about:

- Disease/problem faced
- Doctor consulted
- Hospital visited
- Treatment duration
- Approximate cost spent
- Medicines prescribed
- Recovery experience
- Doctor communication quality
- Hospital cleanliness
- Waiting time
- Staff behavior
- Whether treatment worked
- Whether they recommend the doctor/hospital
- Anonymous mode
- Optional bill/document verification later

These reviews will be stored in MongoDB and used later for:

- Doctor ranking
- Hospital ranking
- Cost transparency
- AI recommendations
- Fake review detection
- Patient satisfaction analytics


2. DATABASE DESIGN
------------------

We should create a new MongoDB model:

server/models/Review.js

Suggested fields:

- patient: ObjectId reference to AuthUser
- doctor: ObjectId reference to Doctor
- hospitalName: String
- hospitalId: optional ObjectId reference to Hospital
- disease: String
- treatment: String
- treatmentDuration: String
- approximateCost: Number
- medicines: String
- recoveryExperience: String
- doctorCommunication: Number, 1 to 5
- hospitalCleanliness: Number, 1 to 5
- waitingTime: Number, minutes
- staffBehavior: Number, 1 to 5
- treatmentWorked: Boolean
- wouldRecommend: Boolean
- overallRating: Number, 1 to 5
- reviewText: String
- anonymous: Boolean
- verifiedPatient: Boolean, default false
- moderationStatus: "pending", "approved", "rejected", "flagged"
- sentiment: "positive", "neutral", "negative"
- flags: Array of strings
- createdAt / updatedAt timestamps

Important:

Reviews should not immediately affect public ranking unless moderationStatus is approved.


3. BACKEND API ROUTES
---------------------

Create:

server/routes/reviewRoutes.js

Required routes:

POST /api/reviews
Purpose: Submit a new patient review.

GET /api/reviews/doctor/:doctorId
Purpose: Fetch approved reviews for a doctor profile page.

GET /api/reviews/hospital/:hospitalId
Purpose: Fetch approved reviews for a hospital page.

GET /api/reviews/me
Purpose: Fetch reviews submitted by the logged-in patient.

PATCH /api/reviews/:id/moderation
Purpose: Future admin route to approve/reject/flag reviews.

For now, since we do not have JWT fully implemented, frontend can send patientId from the current logged-in user. Later, JWT middleware should protect this properly.


4. BACKEND CONTROLLER LOGIC
---------------------------

Create:

server/controllers/reviewController.js

Functions:

createReview()
- Validate required fields.
- Check patient exists.
- Check doctor exists.
- Prevent empty or very short review text.
- Prevent rating values outside 1 to 5.
- Calculate simple sentiment.
- Save review with moderationStatus = "pending" or "approved".

getDoctorReviews()
- Return only approved reviews for a doctor.
- Hide patient identity if anonymous = true.

getHospitalReviews()
- Return only approved hospital reviews.

getMyReviews()
- Return reviews submitted by current patient.

moderateReview()
- Admin/moderator updates status.


5. VALIDATIONS
--------------

Frontend and backend should both validate.

Required fields:

- doctor
- disease
- treatment
- approximateCost
- doctorCommunication
- hospitalCleanliness
- staffBehavior
- treatmentWorked
- wouldRecommend
- overallRating
- reviewText

Validation rules:

- approximateCost must be 0 or above.
- waitingTime must be 0 or above.
- rating fields must be between 1 and 5.
- reviewText should be at least 20 characters.
- disease and treatment should not be empty.
- patient must be logged in.
- doctors should not submit patient reviews.

10. UPDATING DOCTOR SCORES
--------------------------

Later, once reviews are approved, we should calculate doctor stats:

- averageRating
- communicationScore
- affordabilityScore
- recoveryScore
- recommendPercentage
- averageWaitingTime
- reviewCount

These values can either:

- be calculated live from reviews, or
- be stored in Doctor model and updated whenever a review is approved.

Recommended first version:

Calculate live from approved reviews.

Recommended optimized version later:

Store aggregated score fields in Doctor model.


11. SIMPLE SENTIMENT ANALYSIS
-----------------------------

First version can be rule-based.

Positive words:

- good
- excellent
- helpful
- recovered
- satisfied
- recommend
- caring
- clean

Negative words:

- bad
- rude
- costly
- delayed
- poor
- not recovered
- worst
- unclean

If positive count > negative count:

sentiment = positive

If negative count > positive count:

sentiment = negative

Otherwise:

sentiment = neutral

Later, this can be replaced with real NLP/AI.


12. FAKE REVIEW PROTECTION - FIRST VERSION
------------------------------------------

Basic rules:

- One patient cannot submit multiple reviews for same doctor within 7 days.
- Very short reviews are rejected.
- Reviews with too many repeated words are flagged.
- Reviews with abusive words are flagged.
- Extremely negative review with no explanation is flagged.
- New accounts can be marked as unverified initially.

Review statuses:

- pending
- approved
- rejected
- flagged

For now:

Set all reviews to pending, or auto-approve normal reviews and flag suspicious ones.

Recommended first build:

Auto-approve clean reviews, flag suspicious reviews.


13. PRIVACY AND ETHICS
----------------------

Important rules:

- Do not show patient phone/email publicly.
- Anonymous reviews should hide patient name.
- Do not allow medical accusations without moderation.
- Use wording like "patient-reported experience", not "proven fact".
- Add medical disclaimer near reviews.
- Allow doctors/hospitals to respond professionally later.

Suggested disclaimer:

"Reviews are patient-reported experiences and should not be treated as medical advice. HealthBridge moderates reviews for safety, privacy, and fairness."
