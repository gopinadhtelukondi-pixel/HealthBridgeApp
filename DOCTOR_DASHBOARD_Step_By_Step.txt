1. WHAT WE ARE BUILDING
-----------------------

The Doctor Dashboard is a private, doctor-only interface that allows doctors to:

1. View all reviews submitted about them
2. Filter reviews by moderation status (pending, approved, flagged)
3. Read detailed patient feedback with ratings
4. Respond to reviews publicly with professional comments
5. Edit and update their profile information
6. View analytics about their reviews and ratings
7. Manage their medical credentials and certifications

This dashboard helps doctors:
- Respond to patient concerns professionally
- Improve their services based on feedback
- Build trust through transparent engagement
- Maintain accurate profile information
- Track patient satisfaction metrics

Key principle: Doctors can only view/edit their own data; admins have broader permissions.


2. USER INPUTS & FEATURES
-------------------------

A. Review Management Section:
   - View all reviews for the doctor's profile
   - Filter by status: All, Pending, Approved, Flagged
   - Sort by: Newest, Oldest, Highest Rating, Lowest Rating
   - Search reviews by keyword
   - Read detailed review with all rating dimensions
   - See patient name/verification status (respecting privacy)

B. Review Response:
   - Add a professional response to each review
   - Character limit: 500 characters (keep it concise)
   - Responses are public and visible to all patients
   - Edit/update response within 24 hours of posting
   - Delete response if needed (admin approval)

C. Profile Management Section:
   - Edit basic info: name, phone, hospital, city
   - Update specialization/specialty
   - Add/update medical license number (NMC ID)
   - Upload/update profile photo
   - Add professional bio/summary (max 500 chars)
   - List medical qualifications/education
   - Add achievements and certifications
   - Update consultation fee
   - Update experience years
   - Add tags/specializations (cardiac, diabetes care, etc.)
   - Toggle verified status (admin-only, informational)
   - NABH certification status (informational)

D. Analytics Dashboard:
   - Average overall rating
   - Average rating per dimension (communication, recovery, cost, waiting time, staff behavior)
   - Total reviews received
   - Verified vs anonymous review breakdown
   - Recommendation percentage (% patients would recommend)
   - Recent review trends (last 30 days, 90 days, all time)
   - Review sentiment breakdown (positive, neutral, negative)
   - Response rate to reviews

4. API ROUTES (server/routes/doctorRoutes.js)
---------------------------------------------

NEW ROUTES FOR DOCTOR DASHBOARD:

GET /api/doctors/dashboard/:doctorId
Purpose: Fetch doctor's own dashboard data (reviews count, analytics, etc.)
Auth: Doctor-only (must match :doctorId)
Returns: { totalReviews, averageRating, reviews: [...], analytics: {...} }

PUT /api/doctors/:doctorId/profile
Purpose: Update doctor's profile information
Auth: Doctor-only (must match :doctorId)
Body: { name, phone, hospital, city, spec, fee, exp, bio, education, certifications, achievements, tags }
Returns: { message: "Profile updated", doctor: {...} }

GET /api/doctors/:doctorId/reviews
Purpose: Get all reviews for a doctor (with filters)
Query params: ?status=pending|approved|flagged|all&sort=newest&page=1&limit=10
Auth: Doctor-only (must match :doctorId) OR Admin
Returns: [{ ...review with full details }]

POST /api/reviews/:reviewId/response
Purpose: Add a response to a review
Auth: Doctor-only (doctor who wrote the review) OR Admin
Body: { text: "Thank you for the feedback..." }
Returns: { message: "Response added", review: {...} }

PUT /api/reviews/:reviewId/response
Purpose: Update an existing response
Auth: Doctor-only (doctor who wrote the response) OR Admin
Body: { text: "Updated response..." }
Returns: { message: "Response updated", review: {...} }

DELETE /api/reviews/:reviewId/response
Purpose: Delete a response
Auth: Doctor-only (doctor who wrote the response) OR Admin
Returns: { message: "Response deleted" }

GET /api/doctors/:doctorId/analytics
Purpose: Get review analytics for dashboard
Auth: Doctor-only (must match :doctorId) OR Admin
Returns: { 
  totalReviews, 
  averageRating, 
  avgCommunication, 
  avgRecovery, 
  avgCost, 
  avgWaitingTime, 
  avgStaffBehavior,
  recommendationPercentage,
  verifiedReviewCount,
  sentimentBreakdown: { positive, neutral, negative },
  responseRate
}

7. AUTHENTICATION & AUTHORIZATION
---------------------------------

Middleware Check (protect /doctor/dashboard routes):

```javascript
const isDoctorOwner = (req, res, next) => {
  const { doctorId } = req.params;
  const user = req.user; // from auth token
  
  if (!user) return res.status(401).json({ message: "Unauthorized" });
  if (user.role !== 'doctor') return res.status(403).json({ message: "Forbidden" });
  if (user.doctorProfile !== doctorId && user.role !== 'admin') {
    return res.status(403).json({ message: "Cannot access other doctor's dashboard" });
  }
  next();
};
```

Apply to all doctor dashboard routes.

10. HOOKS
--------

Create src/hooks/useDoctorDashboard.js:

```javascript
export const useDoctorDashboard = (doctorId) => {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    fetchDoctorDashboard(doctorId)
      .then(setData)
      .catch(setError)
      .finally(() => setLoading(false));
  }, [doctorId]);

  return { data, loading, error };
};

export const useDoctorReviews = (doctorId, filters = {}) => {
  const [reviews, setReviews] = useState([]);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState(null);

  const fetch = async () => {
    setLoading(true);
    try {
      const data = await fetchDoctorReviews(doctorId, filters);
      setReviews(data);
    } catch (err) {
      setError(err);
    } finally {
      setLoading(false);
    }
  };

  useEffect(() => {
    fetch();
  }, [doctorId, filters]);

  return { reviews, loading, error, refetch: fetch };
};

export const useReviewResponse = () => {
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState(null);

  const addResponse = async (reviewId, text) => {
    setLoading(true);
    try {
      const data = await addReviewResponse(reviewId, text);
      return data;
    } catch (err) {
      setError(err);
      throw err;
    } finally {
      setLoading(false);
    }
  };

  return { addResponse, loading, error };
};
```


11. API SERVICE FUNCTIONS (src/services/api.js)
---------------------------------------------

Add these functions:

```javascript
export const fetchDoctorDashboard = (doctorId) =>
  api.get(`/doctors/dashboard/${doctorId}`).then(r => r.data);

export const fetchDoctorReviews = (doctorId, filters = {}) => {
  const params = new URLSearchParams(filters);
  return api.get(`/doctors/${doctorId}/reviews?${params}`).then(r => r.data);
};

export const fetchDoctorAnalytics = (doctorId) =>
  api.get(`/doctors/${doctorId}/analytics`).then(r => r.data);

export const updateDoctorProfile = (doctorId, data) =>
  api.put(`/doctors/${doctorId}/profile`, data).then(r => r.data);

export const addReviewResponse = (reviewId, text) =>
  api.post(`/reviews/${reviewId}/response`, { text }).then(r => r.data);

export const updateReviewResponse = (reviewId, text) =>
  api.put(`/reviews/${reviewId}/response`, { text }).then(r => r.data);

export const deleteReviewResponse = (reviewId) =>
  api.delete(`/reviews/${reviewId}/response`).then(r => r.data);
```

15. SECURITY CONSIDERATIONS
---------------------------

1. Authentication:
   - All dashboard routes require login
   - Verify user is a doctor
   - Verify doctor owns the profile being viewed/edited

2. Authorization:
   - Doctors can only edit their own profile
   - Doctors can only add responses to their own reviews
   - Doctors cannot change their own verified status (admin-only)
   - Doctors cannot moderate other doctors' reviews

3. Input Validation:
   - Validate all text inputs server-side
   - Sanitize HTML/script tags from responses
   - Rate limit API endpoints
   - Prevent duplicate submissions (debounce)

4. Data Privacy:
   - Don't expose patient personal info
   - Hide contact details from public
   - Allow anonymous reviews to stay anonymous
   - Audit log all profile changes
